# Adscope 前端 Stellar UI 重构设计

## 目标

将现有 Nuxt 管理台和用户端从原生表单、按钮和分散样式迁移到 `@stellar/ui@0.3.0`，形成统一的页面壳、表单、表格、状态反馈和危险操作体验，同时保留现有路由、API 契约和 AD 业务边界。

## 设计原则

- Center 数据与现有 API 是事实源，前端不新增业务状态模型。
- Stellar UI 负责通用组件、主题和交互基础；Adscope 业务组件负责域、OU、用户、组和同步语义。
- 页面统一表达当前上下文、主要操作、数据区和状态区。
- 所有异步操作必须区分加载、成功、失败、空数据和过期状态。
- 高风险操作必须先说明对象和影响，再执行确认。
- 不保留与 Stellar UI 重复的基础按钮、输入框、弹窗和状态样式。

## 页面结构

### 用户端

`/login` 使用居中的登录面板，包含品牌、用户名、密码、错误提示和提交状态。`/me` 使用资料概览、联系方式编辑和密码修改三个分区。`/authorize` 使用授权方、当前用户、权限范围和确认/拒绝操作四个区域。

### 管理端

管理端使用固定侧栏、顶部身份操作区和内容区。目录页以域和 OU 为上下文，左侧展示 OU 树，右侧展示对象表和创建操作。域页展示域配置、启用状态、Connector 状态、revision 和 key 操作。客户端页展示 OAuth Client、回调地址、权限范围和密钥操作。同步页按域展示目录与凭据 revision、同步状态、错误信息和刷新操作。

## 组件边界

- `AdminShell`：管理端布局、导航、凭证入口、主题和全局刷新。
- `PageHeader`：标题、说明和主要操作。
- `StatusLine` / `StatusBadge`：统一异步状态和实体状态。
- `Modal`：仅保留业务内容包装，底层 overlay 使用 Stellar UI。
- `DomainTable`、`ObjectTable`、`SyncTable`、`OAuthClientTable`：只负责业务列和行操作。
- 各类 Editor：只负责业务字段、字段错误和提交模型。
- `useToast`、`useConfirm`：统一成功、失败和危险操作反馈。

## 迁移批次

1. 接入组件库、Tailwind、主题和全局样式顺序，重构管理端壳层。
2. 重构登录、个人资料和 OIDC 授权页面。
3. 重构域、OU、用户、组和目录对象页面。
4. 重构 OAuth Client 和同步状态页面。
5. 清理旧基础样式，执行类型检查、构建和页面契约验证。

## 验收标准

- 所有现有页面路由继续可访问，API 调用和业务字段不变。
- 基础交互统一使用 Stellar UI，不再新增原生基础控件样式。
- 保存、删除、禁用、密码重置和 key 操作具有统一反馈和确认。
- 页面具备加载、错误、空状态和成功反馈。
- `bun run typecheck` 和 `bun run build` 通过。
