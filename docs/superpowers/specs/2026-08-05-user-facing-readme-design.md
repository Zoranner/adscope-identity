# 用户向 README 设计

## 目标

README 作为项目的用户入口，帮助普通用户、业务管理员和部署人员快速判断系统用途，了解主要功能，并找到部署和参考文档。正文直接说明产品职责，不展开内部实现。

## 内容结构

README 保留四部分：

- 项目简介：说明中心统一维护组织、账号、组和密码，并同步到多个独立 AD 域。
- 主要功能：合并说明普通用户自助、管理员维护和多域同步能力。
- 部署方式：说明 Center 使用 Docker、Connector 使用 Windows 服务，并给出部署与安全文档入口。
- 文档入口：集中链接产品概览、部署说明、安全要求和技术参考。

系统工作方式融入项目简介，普通用户和管理员入口融入主要功能，不再单独设置架构、使用入口或工程实现章节。

## 表达边界

README 使用面向使用者的中文，优先写业务对象、操作和结果。`revision`、数据表、API、密码密文实现和 crate 结构等工程细节由参考文档承载。

涉及单向同步、中心事实源、传输保护和域内改密限制的内容保留必要边界，不使用宣传式表述，也不承诺未经真实环境验证的运行效果。

## 验收要求

- 四部分结构完整，标题不使用序号。
- 普通用户、管理员和部署人员都能找到对应信息。
- Center Docker 服务和 Connector Windows 服务的部署边界准确。
- 所有相对链接指向仓库内现有文件。
- README 不包含阶段说明、待办清单或内部实施过程。
